Architecture

Six layers, one record of truth

The design principle is that files, not conversations, hold the state. A chat is disposable. The record is not.

Data

One record of truth

Every opportunity is a structured record: company, role, source, status, a step ladder from Analyzed to Accepted with dates, contacts with tier and send state, an activity log, signals and flags. The spreadsheet tracker is an export regenerated from the record, never a second copy of the truth.

Generation

Documents from code

Résumés and cover letters are produced by generator scripts built on a master, one per role, from a single verified job-history file. A fact corrected once propagates to every document on rebuild. Twenty-five résumé generators and twenty-four cover-letter generators exist today.

Gates

Nothing ships unchecked

Four gates run on every document before I see it: a written quality gate, an ATS parser gate, a mechanical provenance gate that fails a document on any unverified tool, figure or claim, and a cold read as the hiring manager. Details below.

Presentation

A self-rebuilding dashboard

A 2,500-line builder renders the record into a single self-contained application: pipeline stages, momentum-based hot detection from the last five days of activity, weighted scoring, next actions phrased as people and meetings, embedded documents, and one-click commands that hand a task back to an agent. Nobody edits it by hand.

Skills

Written procedures the agents load by name

Each skill is a procedure with hard rules: what to do, in what order, and what never to do. The agent loads one by name and follows it. The library is listed below.

Integration and memory

MCP, and a rulebook written when the rule is learned

Agents reach Gmail, Google Drive, Chrome, Microsoft 365 and the local file system through Model Context Protocol. A standing rulebook records every ruling the day it is made, with the incident that caused it; a session-state file is what any new session reads first.

Governance

The part that separates running a platform from using a chatbot

Approval on every outbound action

No message, application or email leaves without me reading that specific item and approving it in the moment. No batch approvals, no standing permission. The dashboard can queue a send; only my approval of that message executes it.

A written trust boundary

The agents do not submit applications autonomously; I drive the portal. Full-agentic runs are tested only on opportunities I designate as expendable, at my initiation. Trust is earned first; the record has to show the system deserves more room before it gets it.

Rules come from incidents

The rulebook was not written in advance. It is a log of real failures converted into standing rules, each with the incident attached.

A tool name inferred from context reached twelve résumés before I caught that I had never used it. Rule: every tool comes from a verified list that only I can edit.

An email built with embedded images rendered blank in Gmail. Rule: build for the delivery platform and verify in the destination before sending.

A phrase from an unrelated thread contaminated a strategy brief. Rule: high-stakes work gets a clean session with only its own material in it.

A challenged term is a removed term

If I question where a claim came from, it comes off immediately and returns only if I say keep. Leaving it in pending a ruling is how errors ship twice.

Optimize for the meeting

My own evidence says live conversations convert and cold portals stall, so the system is tuned to earn meetings rather than to win on paper: every opportunity carries the shortest path to a human, and unsent outreach outranks ready applications. That is a strategic decision made by the person, from evidence, and no prompt made it.

Accuracy over warmth

An unverified personal connection is never used to make a note warmer. A clean professional note beats a warm note with a false claim in it.

Skills library

Reusable agent procedures I wrote

job-application-kit

Posting capture, fit and salary analysis, an ATS résumé tailored to the posting, a custom cover letter, a tracker row and a dashboard entry, then the gates.

targeted-networking-campaign

A tiered contact list for a company, verified profile by profile, only real connection points, drafted notes in my voice. Hard rules: never a same-title peer, never over the hiring manager's head, never an unverified affinity claim, warm paths before cold notes.

interview-rehearsal

Compresses everything known about an interview into a roleplay brief for a separate session, then scores the transcript against a fixed rubric so repeat rehearsals are comparable.

update-dashboard

Rebuilds every document whose generator changed, re-runs the gates, re-embeds the PDFs and refreshes the dashboard.

ai-findings-share

Researches a question and sends the findings as a formatted email, behind a send gate, with a disclosure footer.

monte-carlo-document-check

A review-and-revise loop for anything going to a third party: a cold-read agent scores the document as the recipient would, an editor agent applies the edit list under hard rules, the outputs rebuild and verify, and the next round starts from the new version until the scores plateau.

skill-creator and the document skills

Used to write and revise the procedures above, plus the standard document skills for Word, PDF, PowerPoint and Excel output.

Gates

What runs before I see a document

  • Quality gate. A written truth check (every tool, company, number and date must trace to me or to the verified history file), tense and date check, American spelling, voice rules. Each rule cites the incident that caused it.
  • ATS gate. An in-house parser check: single column, standard headings, no tables or text boxes, consistent dates, text-layer PDF, metadata. House rule: fix the detector, never the truth.
  • Provenance gate. A mechanical fabrication check that fails a PDF on banned or false terms, tools not on the verified list, paraphrase drift in company descriptors, present-tense claims about a past employer, and stale figures.
  • Hiring-manager pass. The rendered PDF read cold as the person who will receive it, confirming every claimable requirement is visibly answered on the page.
Findings

What I have learned about where these systems fail

  • Fabrication happens by paraphrase, not invention. The model rewords a verified fact into nearby language that echoes what the reader wants. The defense is a verified vocabulary and a mechanical check, not a reminder to be careful.
  • Confidence is not evidence. Word counts stated without counting; figures that trace to nothing. Anything that matters gets measured.
  • Design from description does not work. Taste cannot be specified in prose. Give the tool the real assets and a written brief, then let a purpose-built tool do the visual work.
  • The platform is part of the deliverable. An artifact that renders where it was made and fails where it lands is a failure. Test in the destination.
  • Long contexts contaminate. A session carrying weeks of unrelated work leaks vocabulary across threads. High-stakes work gets a clean room and a handoff document.
  • The human owns the facts, the strategy and the go decision. Every substantive correction in this system has come from me knowing my own story better than the model does, and the system is built so that my correction wins immediately.
Applied

How the TriFlow assessment was produced

The written responses and the case study submitted on 2 September 2026 were built inside this system. What ran, specifically:

  • A clean room. The work ran in a dedicated session seeded with a handoff document containing only TriFlow material: the assessment verbatim, the nine exhibits, the email trail, and a single résumé as the only permitted pool of claims about my experience.
  • A workbook first. Every input in the case-study workbook is cited to its exhibit; every assumption is labeled A1 to A16 and highlighted; 233 live formulas, recalculated and checked for errors on every rebuild. The memo was written from the workbook, not the other way round.
  • A verification script. Every rebuild of the documents runs a script that enforces the page limit, word limits, a punctuation rule, a vocabulary rule, and a check that nothing in the text speaks to anyone but the reader. Nothing shipped without it passing.
  • Cold-read review. Fresh agents with no context on me read the submission as the panel's own AI would, scored it against the published six-dimension rubric with two independent scorers, spot-checked the arithmetic against the exhibits, and wrote a numbered edit list.
  • Guarded editing. A separate editor agent applied each list under hard rules: never add a fact about my experience, never change a number, no new claims, and every escalated number handed back to me to fix in the workbook by hand.
  • The loop. Three full review-and-revise rounds and a final scoring pass. The loop found and fixed a budget miscount, a margin applied to the wrong line, a missing crew-week allocation, and an escalator booked at delivery margin when it is pure price. The case-study score rose from 3.98 to 4.25 on the panel's own rubric, as read by a cold agent.
  • Delivery in the destination. The documents were rendered, checked page by page, and published to a page on this site so the panel reads a link that stays current, with server-side and client-side measurement on the page.

The judgments, the stories and the numbers I chose to stake the plan on are mine. The system's job was to make sure they were checked.
